API Reference

The Bridge v4.0.0 — RF Signal Detection Backend. All endpoints are prefixed with their router path.

Authentication

All API endpoints (except GET /api/version) require authentication via an API key.

HTTP Endpoints

Pass the key in the X-API-Key header or as an api_key query parameter:

curl -H "X-API-Key: YOUR_KEY" https://bridge.example.com/api/health

WebSocket Endpoints

Use the Sec-WebSocket-Protocol header (preferred):

Sec-WebSocket-Protocol: bridge-v1, YOUR_API_KEY

Query parameter auth (?api_key=xxx) is deprecated and can be disabled with BRIDGE_WS_QUERY_AUTH=disabled.

RBAC Roles

Roles are hierarchical — higher roles inherit all lower permissions.

RoleLevelPermissions
SENSOR0Edge sensor devices, ingest-only
NODE1Edge nodes, ingest + read own status
VIEWER2Read-only dashboard access
ANALYST3Read + write detections, alerts, investigations
ADMIN4Full access including user management, system config

API Versioning

The Bridge uses header-based versioning. Include X-API-Version: 1 in requests. Currently supported: ["1"]. Responses include X-API-Version in the header. Requests with unsupported versions receive 400.

Rate Limiting

Sliding window rate limiting per API key. Default: 300 requests/minute (configurable). Sensitive endpoints (key creation, admin) limited to 10/minute. Exceeded limits return 429 with Retry-After header.

WebSocket connections: max 10 concurrent per IP, max 30 connections/minute per IP.

Health & Status

Prefix: /api

GET /api/version No Auth

Version discovery endpoint. No authentication required.

Returns api_version, server_version (the API server's version, 4.0.0, unchanged across releases), release (the image's release tag such as v0.2.0, main-<sha12> for a main build, or dev for any other build), ws_protocol, and supported_versions.

curl https://bridge.example.com/api/version
GET /api/health VIEWER

Basic health probe. Returns status, version (4.0.0), release (as in /api/version), UTC timestamp, security_warnings and crypto_key_persistence: whether imported protocol decryption keys are saved (enabled, disabled, invalid_key, wrong_key, error; see GET /api/crypto/status). A Protocol decryption keys: ... entry in security_warnings appears only when keys are at risk: BRIDGE_KEYSTORE_KEY invalid or changed, or repeating BRIDGE_MFA_KEY or BRIDGE_AUDIT_KEY (which the gateway holds), saved keys left unloaded, a database error, or imported keys that a restart would lose. A Pre-migration copy guard disabled: ... entry appears while BRIDGE_ALLOW_MIGRATION_WITHOUT_BACKUP is set.

curl -H "X-API-Key: $KEY" https://bridge.example.com/api/health
GET /api/status VIEWER

Live system-wide status: node counts (active/stale/offline), alert count, job counts, detection metrics (24h totals, detections/sec), active anomalies, active frequencies, uptime.

GET /api/metrics VIEWER

Operational metrics: ingest rate, WS client counts (detections, anomalies, spectrum, wifi), database size and row count, cache statistics.

GET /api/edge/install.sh No Auth

Edge onboarding: the host installer for the heartbeat agent, as text/x-shellscript, piped into sudo bash on the edge host (it needs a NODE-role API key at run time, so fetching it grants nothing). The bridge fills in its release tag, so the edge checks out the release the server runs (main for a dev or main-<sha12> build; --ref overrides). Re-runs keep /etc/sigrift-edge.env and the CA certificate.

f=$(mktemp) && curl -fsSL --cacert /etc/sigrift-edge/ca.pem -o "$f" https://bridge.example.com/api/edge/install.sh && sudo bash "$f"; rm -f "$f"

Download first (as above): piped into bash, a failed download runs an empty script and exits 0. A new --api-url needs --api-key too, and does not reuse the kept gateway trust.

Known-pattern scope: an explicit pattern body uses freq_min_hz, freq_max_hz, signal_class, node_id and optional note. Set signal_class to the exact literal "*" for any modulation; otherwise it must be an exact class matching [a-zA-Z0-9_/.-]{1,128}. Embedded wildcards are rejected. The inclusive frequency range and node still apply; node_id: null explicitly means all nodes. Power is never a matching criterion. For the per-detection baseline endpoint, the reviewed frequency range and node scope must include the source detection; its signal class must match unless "*" is selected. Edits also require the current revision.

Direct POST /known-signals uses the same validated fields, with an explicit node_id (a receiver ID or null for all nodes). It requires no existing detection and returns source_detection_id: null for a newly created direct rule. Identical matching scope retries return the existing pattern without changing its note or duplicating its audit record. The rule and known_signal_create audit event commit together; persistence failure returns 503 without claiming success. Existing matching patterns retain their original provenance.

Preview defaults retain the actual source class. Omitting the per-detection baseline body, and bulk baseline requests, keep the existing class-specific behavior. The browser’s new reviewed form explicitly sends "*" when its frequency-only checkbox is selected. These patterns change future RF alerting only; detection scores and history remain intact.

API Keys

Prefix: /api/keys

POST /api/keys/ ADMIN (master)

Create a new API key. Returns the raw key once. Sensitive rate limit (10/min).

Request Body (KeyCreate)

FieldTypeDescription
key_idstringUnique key identifier. The key is an ANALYST key, except an id starting with node_, rtlsdr_, hackrf_, sensor_, edge_ or sdr_: that is a NODE key (the response's role)
descriptionstringHuman-readable description
node_idstring?Optional: bind to specific node
expires_in_hoursnumber?Optional lifetime in hours: finite and at most 10000000, else 422. Capped at BRIDGE_MAX_KEY_LIFETIME_DAYS (default 365); omitted, zero or negative gets that maximum.
GET /api/keys/ VIEWER

List all keys with metadata. Raw keys and hashes are never returned. Each row's expires_at is the instant bridge auth applies (a stored value without a UTC offset is UTC), and expired is true when bridge auth rejects the key as expired: its expires_at has passed, or the stored value cannot be parsed (then expires_at is null, which alone would read as never expiring). A disabled or revoked key is not expired. GET /api/admin/keys lists the same flag next to the stored expires_at. The gateway reads a hand-edited expires_at with its own parser and can disagree: 2999-01-01T00:00 (no seconds), for example, is not expired here but is refused by the gateway's own routes.

DELETE /api/keys/{key_id} ADMIN (master)

Revoke an API key permanently.

PUT /api/keys/{key_id}/rotate ADMIN (master)

Rotate an existing key. Returns the new raw key once. Sensitive rate limit.

System Configuration

Prefix: /api/admin

GET /api/admin/detection-config ADMIN

Get/set detection thresholds, dimension weights, and auto-snooze config. PUT to update: send only the keys to change. wifi_dimension_weights, rf_dimension_weights and protocol_detection merge into the stored objects; every other key replaces its value.

Every value is checked before anything is stored. Thresholds, scores and rf_min_confidence_floor: numbers from 0 to 1. Seen counts, wifi_anomaly_cooldown_seconds and rf_min_learning_detections: whole numbers from 0 to 1000000000; snooze hours: whole numbers from 0 to 87840. Weights: numbers from 0 to 1, at most 64 per object as stored, summing to at most 2.0 as stored. protocol_detection: true / false for protocols the bridge lists. auto_rescan: the POST /api/admin/auto-rescan body. iq_capture_enabled: true / false. Strings, booleans, null, NaN and infinities are not numbers, and a key the bridge does not know is refused unless it is sent with the value already stored, so the config a GET returns can be sent back as is. A refused value makes the request a 422 whose string detail names each problem, and nothing changes.

Crypto Key Management

Prefix: /api/crypto — Protocol key management for decryption (Meshtastic AES, DMR, P25).

Imported keys are saved in the bridge database, encrypted with BRIDGE_KEYSTORE_KEY, when it is set, and loaded again at startup under the same key_id and created_at; without it they are kept in memory only and lost at every restart. The built-in keys are never saved. Every endpoint answers 503 Crypto key store not initialised when the bridge has no key store.

GET/api/crypto/keysANALYST

List the keys the bridge holds: the built-in defaults and every imported key (metadata only — key material is NEVER returned). Query param: protocol. Fields: key_id, protocol, algorithm, label, source, key_len, created_at, metadata, persisted. persisted is true for a key saved in the database (loaded again at startup).

POST/api/crypto/keysADMIN

Import a key. Body: {protocol, key_name, raw_key_hex, algorithm}; protocol and algorithm at most 32 characters, key_name 1–128, raw_key_hex at most 256 key bytes (two hex digits per byte; : and spaces allowed and not counted; at most 1024 characters in all): longer values get 422. Returns 201 with {key_id, protocol, label, persisted}; persisted says whether the key was saved in the database. Malformed hex gets 400. No error repeats the key: neither the 400 detail nor any 422 (the usual input of each 422 error is left out under /api/crypto/). 503 when the key could not be saved: nothing was imported. An import and a revoke of the same key run one after the other.

DELETE/api/crypto/keys/{key_id}ADMIN

Revoke a key: deletes its saved row from the database (with SQLite secure_delete, then a passive WAL checkpoint), then zeroes it in memory. Returns {ok, revoked}. 404 for an unknown key. 503 when the saved row could not be deleted: the key was not revoked and stays usable. Revoking a built-in key removes it until the next start. Copies of the database made before the revoke (the kept detections.db.pre-migration, backups) still hold the row.

GET/api/crypto/statusANALYST

Whether imported keys are saved. Returns {persistence, loaded, not_loaded, memory_only, message}: persistence is enabled (imports are saved), disabled (BRIDGE_KEYSTORE_KEY not set: memory only), invalid_key (not a Fernet key), wrong_key (it decrypts none of the saved keys: they are left in the database, unloaded, and new imports stay in memory), or error (the saved keys could not be read); loaded and not_loaded count the saved keys loaded and left in the database at startup; memory_only the imported keys a restart would lose; message is the sentence the console shows above the key list.

POST/api/crypto/decryptANALYST

Manual decrypt. Body: {payload_hex, protocol, key_id?, packet_id?, source_node?}. Returns {success, plaintext_hex, algorithm, key_id, confidence}.
